# Руководство по проекту для ИИ-агента (Agent Handoff & Context)

Этот файл содержит полный контекст архитектуры, принятых технических решений, особенностей внешних API в Беларуси и строгих инвариантов проекта **«Кадастровая карта Республики Беларусь»**.

---

## 1. Назначение проекта

Веб-приложение интерактивной карты зданий Республики Беларусь на **FastAPI**, **PostGIS / SQLite** и **MapLibre GL JS** (режим просмотра `Read-Only`).
* Отображает карту всей Беларуси с капитальными строениями из OpenStreetMap (2D/3D экструзия по реальной этажности). Синтетические земельные участки и выдуманные кадастровые паспорта **не отображаются**.
* Позволяет нажать на любое здание на карте РБ и просмотреть в боковой панели:
  1. **Все организации внутри здания** (магазины, банки, аптеки, кафе, ИТ-офисы, госорганы, действующие и исключённые субъекты ЕГР РБ) с указанием этажа, помещения, УНП, ОКЭД, времени работы, телефона и сайта. Для ЕГР есть ссылка «Доп. информация» на карточку субъекта.
  2. **Паспорт объекта по данным OpenStreetMap**: область, район, адрес, тип строения, этажность, материал стен, год постройки, площадь по контуру и координаты. Официальные кадастровые/инвентарные номера и кадастровая стоимость **не показываются**, пока не подключён официальный источник НКА.
* Все инструменты и источники данных в проекте **100% бесплатные и открытые (Open-Source)**.

## 2. Стек и команды управления проектом (`uv`)

Проект использует пакетный менеджер **`uv`**, Python `3.12` (зафиксирован в `.python-version`) и лок-файл `uv.lock`.

* **Синхронизация зависимостей:**
  ```powershell
  uv sync
  ```
* **Запуск веб-сервера для разработки:**
  ```powershell
  uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
  ```
* **Запуск автотестов (все 15 тестов должны проходить без ошибок):**
  ```powershell
  uv run pytest -v
  ```
* **Массовая синхронизация с ЕГР Минюста РБ (`egr.gov.by`) и OpenStreetMap API v0.6:**
  ```powershell
  uv run python scripts/sync_egr_and_osm.py
  ```
* **Очистка отображаемых зданий/участков/организаций (записи ЕГР сохраняются):**
  ```powershell
  uv run python scripts/clear_cadastral_data.py
  ```
* **Синхронизация исключённых из ЕГР субъектов и их последних адресов:**
  ```powershell
  uv run python scripts/sync_egr_excluded.py --from-year 1990 --to-year 2026
  ```
* **Пересборка актуальных границ районов и районов городов из OSM:**
  ```powershell
  uv run python scripts/build_admin_boundaries.py
  uv run python scripts/backfill_districts.py
  ```
* **Санитизация уже сохранённых зданий: убрать синтетические участки, этажность-заглушки, материал стен, кадастровые номера из выдачи:**
  ```powershell
  uv run python scripts/sanitize_synthetic_data.py
  ```
* **Запуск промышленного стека с PostgreSQL 16 + PostGIS 3.4 через Docker:**
  ```powershell
  docker compose up --build -d
  ```

## 4. Критические особенности внешних API и сети (ВАЖНО!)

### 4.1. OpenStreetMap: почему используется `/api/0.6/map.json`, а не Overpass API
* Из сетевого окружения пользователя зеркала `overpass-api.de`, `overpass.private.coffee` и `maps.mail.ru/osm/tools/overpass` **недоступны по таймауту (`ConnectTimeout` / `ReadTimeout`)**.
* Вместо них в `app/services/cadastral_service.py` (`fetch_osm_map_box`) используется официальный эндпоинт **OpenStreetMap API v0.6**:
  `GET https://api.openstreetmap.org/api/0.6/map.json?bbox=min_lon,min_lat,max_lon,max_lat`
* Он отвечает за **~0.25–0.4 сек** со статусом `200 OK` и возвращает полный граф `node`, `way`, `relation` выбранного квартала:
  * Контуры всех зданий (`way` с `building=*`),
  * Адресные узлы и входы (`node` с `addr:housenumber`, `addr:street`),
  * Все организации (`node` и `way` с тегами `shop`, `amenity`, `office`, `craft`, `tourism`, `healthcare`, `leisure`, `government`, `diplomatic`, `club`, `industrial`),
  * Дорожный граф (`highway=*`), откуда автоматически извлекаются пары `name` / `name:be` (белорусское название улицы) <-> `name:ru` (русское название улицы) через `register_street_alias`.

### 4.2. Официальный API ЕГР Минюста РБ (`egr.gov.by`)
* Базовый URL: `https://egr.gov.by/api/v2/egr` (Swagger-схема: `https://egr.gov.by/api/v2/api-docs`). Работает бесплатно и без ключей авторизации.
* **ТРЕБОВАНИЕ ПОЛЬЗОВАТЕЛЯ:** показывать и действующие, и **исключённые из ЕГР** субъекты. В `app/services/egr_service.py`:
  1. **`is_egr_entity_active(short_info)`** определяет статус `"Действующий"` (`nksost == 1`, `dto is None`).
  2. **`sync_egr_excluded_addresses()`** загружает исключённых ЮЛ/ИП из `getAllLikvidUL`/`getAllLikvidIP` и их последние адреса из архива `getAddressByPeriod`; в БД они сохраняются со `status_label = "Исключен из ЕГР"`.
  3. **`attach_egr_records_to_building()`** привязывает к дому и действующие, и исключённые записи по точному нормализованному адресу. В `metadata_json.status` передаётся реальный статус ЕГР.
  4. **`is_egr_address_active()`** используется для текущих адресов действующих субъектов; для исключённых допускается последний архивный адрес с городом, улицей и домом.
  5. **`is_egr_go_active(go_info)`** (для госорганов) — `cact == "+"`, `dto is None`, `cstate is None`.

### 4.3. Определение города, области и района по координатам (`app/services/geo_locator.py`)
* Область и префикс СОАТО определяются по **реальным границам областей** из `app/data/belarus_regions.geojson` (geoBoundaries ADM1), а не по грубым прямоугольникам. Это исправляет ошибки вида «Барановичи → Гродно».
* Район определяется по **актуальным границам OpenStreetMap**: `admin_level=6` — 118 районов областей и 10 городов областного подчинения, `admin_level=9` — 24 района внутри городов (Минск 9, Брест 2, Витебск 3, Гомель 4, Гродно 2, Могилёв 2, Бобруйск 2). Данные лежат в `app/data/belarus_districts.geojson` и собираются скриптом `scripts/build_admin_boundaries.py` через Nominatim/OSM (ODbL). Названия районов реальные, не придуманные. Если точка не попадает ни в один городской район (например, часть территории Гомеля/Гродно в OSM), возвращается сам город областного подчинения, а не выдуманный район.
* Если в OSM у здания нет `addr:city` / `addr:town` / `addr:village`, город уточняется через обратное геокодирование **Nominatim** (`nominatim.openstreetmap.org/reverse`) с кэшем и ограничением 1 запрос/сек. Если Nominatim недоступен или город достоверно не определён, `address_city` остаётся пустым, а UI показывает «—». Подстановка ближайшего крупного города или названия области вместо города **запрещена**.
* Обратное геокодирование города можно отключить через `ENABLE_LIVE_REVERSE_GEOCODING=false`; ЕГР-обогащение — через `ENABLE_EGR_ENRICHMENT=false`. Границы районов берутся из локального файла и от сети не зависят.

## 5. Ключевые архитектурные инварианты (НЕ НАРУШАТЬ!)

### Инвариант 1: Никакого смешивания свойств разных зданий (проблема «нескольких домов № 9»)
В городах Беларуси на соседних улицах (и даже в рамках одного квартала как разные корпуса) есть десятки домов с одинаковым номером (например, в центре Минска рядом находятся `пр-т Победителей, 9`, `ул. Городской Вал, 9`, `ул. Володарского, 9`, `ул. Ленина, 9` и два смежных корпуса `ул. Карла Маркса, 9`).
Чтобы свойства и организации одного дома никогда не присваивались другому:
1. **Нормализация и анти-конфликт адресов (`app/services/address_matcher.py`):**
   * `normalize_city` приводит `Мінск -> минск`, `Гродна -> гродно`, `Магілёў -> могилев`.
   * `normalize_street` переводит белорусские названия улиц в русские (`праспект Пераможцаў -> победителей`, `вуліца Валадарскага -> володарского`, `вуліца Гарадскі Вал -> городской вал`).
   * `normalize_housenumber` строго различает номер дома, литеру и корпус: `"9"` != `"9а"` != `"9/1"` != `"19"`.
   * `has_address_conflict` отклоняет любую точку POI, если у нее указана другая улица или другой номер дома/корпуса.
2. **Защита от захвата точек соседнего корпуса (`match_pois_strictly_to_building` в `app/services/cadastral_service.py`):**
   * Если два здания/корпуса имеют общую стену (как `osm_id=586354950` и `osm_id=586354951` на `ул. Карла Маркса, 9`), точка POI, лежащая строго внутри полигона корпуса Б (`other_poly.contains(pt)`), **никогда** не захватывается буфером стен корпуса А.
3. **Разделение объединенных `MultiPolygon` из векторных тайлов (`extract_single_building_polygon`):**
   * Векторные тайлы базовой карты иногда объединяют несколько зданий квартала в один `MultiPolygon`. Функция `extract_single_building_polygon` извлекает **только тот единственный `Polygon`**, внутри которого находится точка клика `(lon, lat)`.
4. **Точный 2D-хиттест на фронтенде (`static/js/app.js`):**
   * В 3D-режиме (`pitch: 45`) крыша высокого здания визуально перекрывает соседние дома. Поэтому клик проверяется по плоскому 2D-слою основания (`cadastral-buildings-footprint`) с проверкой `isPointInsideGeoJSON(clickLon, clickLat, f.geometry)`, а из базового тайла никогда не передается тайловый `props.id` в качестве `osm_id`.

### Инвариант 2: Запрет создания фейковых объектов при клике мимо зданий (`ул. Центральная, стр. ...`)
1. На фронтенде (`static/js/app.js`) запрос `/api/v1/buildings/inspect` отправляется **только** тогда, когда точка клика `(clickLon, clickLat)` реально попала внутрь полигона здания (`osmBuildingFeature` с проверкой `isPointInsideGeoJSON`). Клик по пустому месту, дороге, парку или реке игнорируется.
2. На бэкенде (`get_or_enrich_building_by_coords` в `app/services/cadastral_service.py`) полностью запрещены заглушки `"ул. Центральная"` и `"стр. XX"`, а также генерация фейковых прямоугольников при отсутствии реального здания в точке клика — возвращается `None` (HTTP `404`).
3. Если на контуре здания (`way`) в OSM не прописаны `addr:street` / `addr:housenumber`, `fetch_osm_map_box` автоматически проверяет адресные точки (`addr_nodes`) на периметре и внутри полигона здания.

### Инвариант 3: Только реальные данные в интерфейсе
1. В паспорте объекта показываются только реальные поля OpenStreetMap: область, район (по актуальным границам OSM, включая районы внутри городов), адрес, название, тип строения, `building:levels`, `building:material`, `start_date`, площадь по контуру и координаты.
2. Синтетические кадастровые номера, инвентарные номера, кадастровая стоимость, прямоугольные «земельные участки» и заглушки этажности/материала стен **не должны попадать в UI/API**. Внутренний `cadastral_number` БД используется только как технический уникальный ключ и наружу не выдаётся.
3. Для отсутствующих полей UI показывает «—», а не выдуманное значение. В частности, город не подменяется названием области/района, «Республикой Беларусь» или ближайшим крупным городом. Реальные кадастровые данные могут быть добавлены только после подключения официального источника НКА (см. раздел 4.3).

## 6. Текущее состояние базы данных (`cadastral_rb.db`)

Локальная база `cadastral_rb.db` очищена от демонстрационных/фейковых полигонов и синтетических паспортов:
* **Записей в таблице `egr_records` (`egr.gov.by`):** `9 755` действующих + `22 728` исключённых из ЕГР (последний известный адрес). Всего `32 483`.
* **Реальных капитальных строений (`buildings`):** наполняются кликами по зданиям OSM (на момент обновления — `228`); у всех заполнен реальный `address_district` (район области или район города).
* **Земельных участков (`cadastral_parcels`):** `0` — синтетические прямоугольники больше не создаются и не отображаются.
* **Организаций внутри зданий (`organizations`):** реальные OSM/ЕГР (действующие и исключённые) без заглушек этажа и часов работы (на момент обновления — `770`).
* При клике по любому зданию на всей территории Беларуси паспорт и организации подгружаются из OSM API v0.6 + ЕГР на лету; официальные кадастровые поля не выдумываются.

## 7. Реализованная функциональность: аналитика выделенной области

Статус: **реализовано и покрыто тестами**. Инструмент доступен на карте кнопкой «Выделить область».

### 7.1. Требования пользователя
* Инструмент выделения области на карте двумя фигурами:
  * **прямоугольник** (протянуть мышью);
  * **произвольный полигон** (клики по вершинам, двойной клик/Enter — завершить).
* После завершения фигуры:
  1. все реальные объекты OSM внутри области **импортируются/обновляются в локальной БД**;
  2. статистика строится уже **по локальной БД и по этой же фигуре**.
* Импортировать **все здания**, включая безымянные и без адреса. Организации — все найденные OSM POI + ЕГР по нормализованному адресу.
* Пользователь разрешил пробовать **любую площадь**. Нужно учитывать лимит OSM API (bbox ≤ 0.25 кв. градуса) и резать область на тайлы; при слишком большом числе тайлов возвращать предупреждение/частичный результат, а не падать.
* Статистика должна включать как минимум:
  * площадь области;
  * количество зданий (всего, с организациями, без организаций);
  * количество организаций (всего, OSM, ЕГР);
  * ЕГР: действующие, исключённые, прочие статусы;
  * разбивку по категориям организаций;
  * разбивку по типам зданий;
  * разбивку по городам и районам;
  * счётчики импорта: добавлено/обновлено зданий, добавлено организаций;
  * `data_scope` и `warnings` (если OSM был недоступен или импорт частичный).

### 7.2. Реализованная архитектура
* `app/services/area_import_service.py`:
  * принимает GeoJSON Polygon/MultiPolygon и валидирует его (`is_valid`, ненулевая площадь);
  * режет bbox на тайлы OSM API (`AREA_IMPORT_TILE_SIZE_DEG`, по умолчанию `0.008°`), ограничивает число тайлов (`AREA_IMPORT_MAX_TILES`, по умолчанию `120`) и возвращает частичный результат с предупреждением вместо падения;
  * через `fetch_osm_map_box` забирает здания и POI, объединяет ответы и убирает дубликаты по `osm_id`;
  * фильтрует объекты по `shapely` (пересечение здания с выделенной фигурой, POI — внутри фигуры);
  * делает upsert зданий по `osm_id` без синтетических полей (кадастровый номер — только технический ключ);
  * привязывает OSM-организации через `STRtree` (без O(B×P)) и ЕГР (действующие + исключённые) по нормализованному адресу;
  * для зданий без `addr:city` не вызывает Nominatim и не подставляет ближайший город: `address_city` остаётся пустым, область и район берутся из реальных границ;
  * после импорта считает статистику по локальной БД в пределах той же фигуры.
* `app/api/analytics.py`: `POST /api/v1/areas/import-and-stats`; невалидная геометрия → HTTP `422`.
* `app/schemas/analytics.py` — схемы запроса/ответа (площадь, здания, организации, OSM/ЕГР, статусы, категории, типы, города, районы, счётчики импорта, `data_scope`, `warnings`).
* `static/js/app.js`: постоянно видимые кнопки «Прямоугольник» и «Полигон» в панели инструментов, рисование области, временный `pitch: 0`, отключение кликов/ховеров, слой выделения, панель статистики, обновление слоёв после импорта.
* `static/index.html` + `static/css/styles.css` — видимые кнопки режимов выделения, подсказка режима, панель статистики.
* Тесты `tests/test_area_import.py`: мок OSM-ответа, фильтрация по полигону, дедупликация по `osm_id`, раздельный подсчёт active/excluded ЕГР, невалидная геометрия → 422, статистика по локальной БД без OSM.

### 7.3. Важные ограничения
* OSM API v0.6 `map.json` имеет ограничение по площади bbox; для больших выделений обязательны тайлы и последовательные запросы.
* Импорт всех зданий может заметно увеличить БД; это ожидаемое поведение, пользователь подтвердил.
* Нельзя добавлять синтетические адреса/участки/кадастровые номера. Для зданий без адреса поля остаются пустыми.
* Для городов без `addr:city` в bulk-импорте нельзя делать Nominatim-запрос на каждое здание и нельзя подставлять ближайший город: `address_city` остаётся пустым, область и район берутся из реальных границ.
