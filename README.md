# Кадастровая карта Республики Беларусь (FastAPI + PostGIS/SQLite + MapLibre GL)

Веб-приложение интерактивной карты зданий Республики Беларусь: капитальные строения из OpenStreetMap (2D/3D), организации внутри них, действующие и исключённые субъекты ЕГР, реальные границы районов и районов внутри городов.

Показываются только реальные данные OpenStreetMap и ЕГР. Синтетические земельные участки, выдуманные кадастровые/инвентарные номера и кадастровая стоимость не создаются и не отображаются.

Все используемые инструменты и источники данных в проекте **100% бесплатные и открытые (Open-Source)**.

---

## Возможности

* **Интерактивная карта всей Беларуси (MapLibre GL JS + OpenFreeMap + MVT):**
  * полигоны зданий в 2D и 3D (высота по реальной этажности OSM);
  * векторные тайлы **MVT (`.pbf`)** через PostGIS `ST_AsMVT` или встроенный Python MVT-энкодер;
  * реальные границы районов областей и районов внутри городов (OpenStreetMap) с цветным секторным зонированием, подписями и подсказкой при наведении;
  * города областного подчинения без внутренних районов показываются как город, без выдуманных районов.
* **Клик по любому зданию на карте:**
  * **«Организации внутри»** — OSM POI, действующие и исключённые субъекты ЕГР; категории, этаж/помещение, УНП, ОКЭД, часы работы, телефон, сайт;
  * для записей ЕГР доступна ссылка **«Доп. информация»** на карточку субъекта на `egr.gov.by`;
  * **«Паспорт объекта»** — только реальные поля OSM: область, район, адрес, тип строения, этажность, материал стен, год постройки, площадь по контуру, координаты;
  * если здания ещё нет в локальной БД, сервер подгружает контур и организации из **OpenStreetMap API v0.6** и ЕГР.
* **Универсальный поиск** по адресу, названию здания, организации или УНП с перелётом камеры.
* **Без синтетики:** внутренний технический `cadastral_number` БД не выдаётся как официальный; официальные кадастровые данные могут быть добавлены только после подключения источника НКА.

## Быстрый запуск через `uv`

```powershell
uv sync
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

* Карта: **http://127.0.0.1:8000**
* Swagger API: **http://127.0.0.1:8000/docs**

Запуск с PostgreSQL 16 + PostGIS 3.4:

```powershell
docker compose up --build -d
```

## Обслуживание и синхронизация данных

```powershell
# Активные субъекты ЕГР + кварталы OSM API v0.6 по hotspot-зонам
uv run python scripts/sync_egr_and_osm.py

# Исключённые из ЕГР субъекты и их последние известные адреса
uv run python scripts/sync_egr_excluded.py --from-year 1990 --to-year 2026

# Актуальные границы районов/районов городов из OSM/Nominatim + пересчёт address_district
uv run python scripts/build_admin_boundaries.py
uv run python scripts/backfill_districts.py

# Санитизация уже сохранённых зданий (убрать синтетические поля/участки)
uv run python scripts/sanitize_synthetic_data.py

# Полная очистка отображаемых зданий/организаций (записи ЕГР сохраняются)
uv run python scripts/clear_cadastral_data.py

# Полный дамп OSM Беларуси для будущего импорта
uv run python scripts/download_belarus_osm.py
```

Важно: Overpass API из текущего сетевого окружения недоступен по таймауту, поэтому основная загрузка идёт через официальный **OSM API v0.6 `map.json`**.

## Текущее состояние данных

* `buildings`: реальные здания OSM, загруженные кликами/синхронизацией.
* `organizations`: реальные OSM POI + ЕГР, без заглушек этажа и часов работы.
* `egr_records`: действующие + исключённые из ЕГР субъекты с последними адресами.
* `cadastral_parcels`: `0` — синтетические участки не создаются и не отображаются.

## Аналитика выделенной области

1. В панели инструментов нажмите **«Прямоугольник»** (протянуть мышью) или **«Полигон»** (клики по вершинам, двойной клик/Enter — завершить, Esc — отмена). Кнопка **«Отмена»** появляется только на время рисования.
2. Все реальные объекты OSM внутри области (включая безымянные здания) импортируются/обновляются в локальной БД.
3. Статистика строится по этой же фигуре уже из БД: здания, организации, OSM/ЕГР, действующие/исключённые, категории, типы зданий (на русском), города и районы, площадь области.
4. Большие области режутся на тайлы OSM API; при частичном импорте возвращаются предупреждения.
5. Каждая выделенная фигура и её статистика автоматически сохраняются в **«Журнал областей»** — оттуда их можно открыть повторно или удалить.

API: `POST /api/v1/areas/import-and-stats`, `GET /api/v1/areas/journal`, `GET/DELETE /api/v1/areas/journal/{id}`. Невалидная геометрия возвращает HTTP `422`.
