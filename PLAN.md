# План развития проекта «Кадастровая карта Республики Беларусь»

Статус: рабочее веб-приложение на реальных данных OpenStreetMap и ЕГР. Синтетические участки/паспорта удалены. Следующий крупный этап — аналитика выделенной области.

---

## 1. Стек

* **Бэкенд:** Python 3.12, FastAPI, Uvicorn.
* **БД:** SQLite (`cadastral_rb.db`) для локального режима; PostgreSQL 16 + PostGIS 3.4 в Docker.
* **ORM:** SQLAlchemy 2.0 async + `aiosqlite` / `asyncpg`.
* **ГИС:** Shapely, GeoJSON, MapLibre GL JS, MVT-тайлы.
* **Фронтенд:** HTML5 + CSS3 + Vanilla JS, MapLibre GL JS, OpenFreeMap basemap.
* **Пакеты:** `uv` + `uv.lock`.

---

## 2. Источники данных

1. **OpenStreetMap API v0.6** `https://api.openstreetmap.org/api/0.6/map.json?bbox=...`
   * контуры зданий, адресные узлы, POI, дорожный граф для белорусско-русских алиасов улиц;
   * Overpass API из текущего окружения недоступен по таймауту.
2. **ЕГР Минюста РБ** `https://egr.gov.by/api/v2/egr`
   * действующие субъекты (`nksost=1`);
   * исключённые субъекты (`getAllLikvidUL` / `getAllLikvidIP`) + последние адреса из `getAddressByPeriod`.
3. **Границы:**
   * области — `app/data/belarus_regions.geojson` (geoBoundaries ADM1, реальные границы);
   * районы и районы городов — `app/data/belarus_districts.geojson` из OSM/Nominatim: 118 районов, 24 района внутри городов, 10 городов областного подчинения, fallback-области городов.
4. **Адреса/город:** OSM `addr:*`, Nominatim reverse с кэшем; при недоступности — локальные границы/ближайший известный город.

## 3. Текущая архитектура

### Модели БД

* `Building` — реальное капитальное строение:
  * `osm_id`, контур (`geometry_geojson`), bbox, центр;
  * адрес: область, район, город, улица, дом, индекс;
  * тип, этажность, год, материал стен, площадь по контуру;
  * `cadastral_number` — только внутренний технический ключ, наружу не выдаётся;
  * `inventory_number`/`parcel_id` не используются для синтетики.
* `Organization` — реальные OSM POI и ЕГР:
  * название, категория, подкатегория, УНП, этаж/помещение, часы, телефон, сайт, email;
  * `metadata_json`: источник, статус ЕГР (`Действующий` / `Исключен из ЕГР`).
* `EgrRecord` — локальный индекс ЕГР:
  * действующие и исключённые субъекты, нормализованный адрес для привязки к зданиям.
* `CadastralParcel` — legacy-модель; в рабочем отображении не используется, таблица пуста.

### Основные модули

* `app/services/cadastral_service.py` — клик по зданию, загрузка OSM-квартала, строгая привязка POI к зданию, EGR-обогащение, поиск, GeoJSON.
* `app/services/egr_service.py` — клиент ЕГР, синхронизация действующих/исключённых, привязка по адресу.
* `app/services/geo_locator.py` — области/районы/города, приоритет «район города → город → район области», Nominatim reverse.
* `app/services/address_matcher.py` — нормализация адресов, анти-конфликт домов/корпусов, выделение одного полигона из MultiPolygon.
* `app/services/mvt_encoder.py` — MVT-тайлы.
* `app/services/seed_data.py` — только демонстрационные данные, в рабочем запуске не используется.

### API

* `GET /api/v1/buildings/{id}` — паспорт и организации.
* `GET /api/v1/buildings/by-coords`, `POST /api/v1/buildings/inspect` — клик по карте.
* `GET /api/v1/search`, `GET /api/v1/stats`.
* `GET /api/v1/geojson/buildings`, `/geojson/parcels`, `/geojson/districts`.
* `GET /api/v1/tiles/cadastral/{z}/{x}/{y}.pbf`.

## 4. Ключевые инварианты

1. Не смешивать свойства разных зданий с одинаковым номером дома/корпуса.
2. Не создавать фейковые объекты при клике мимо здания.
3. В UI/API — только реальные данные:
   * синтетические участки, кадастровые/инвентарные номера и стоимость не показываются;
   * отсутствующие поля — «—».
4. Районы — только реальные OSM-границы; никаких выдуманных районов.
5. ЕГР — и действующие, и исключённые субъекты.

## 5. Текущее состояние

* `buildings`: реальные OSM-здания, загруженные кликами/синхронизацией.
* `organizations`: реальные OSM/ЕГР, без заглушек.
* `egr_records`: 9 755 действующих + 22 728 исключённых (всего 32 483).
* `cadastral_parcels`: 0.
* Тесты: 11 проходят.

## 6. Следующий этап: аналитика выделенной области

Согласовано с пользователем:
* фигуры: **прямоугольник** и **произвольный полигон**;
* импортировать **все** здания внутри области, включая безымянные и без адреса;
* пробовать **любую площадь** (с тайлингом OSM API и предупреждениями при частичном импорте);
* схема: выделение → импорт/upsert OSM-объектов в БД → статистика по этой же фигуре из БД.

Планируемые компоненты:
* `app/services/area_import_service.py` — тайлинг bbox, загрузка OSM, upsert зданий, привязка OSM POI и ЕГР.
* `app/api/analytics.py` — `POST /api/v1/areas/import-and-stats`.
* `app/schemas/analytics.py` — схемы запроса/ответа.
* UI: кнопка «Выделить область», рисование, индикатор импорта, панель статистики.
* Статистика: площадь, здания, организации, OSM/ЕГР, действующие/исключённые, категории, типы зданий, города/районы, счётчики импорта, `warnings`.

Ограничения:
* OSM API v0.6 ограничивает bbox; большие области резать на тайлы.
* Не добавлять синтетические адреса/участки/кадастровые номера.
* В bulk-режиме не делать Nominatim-запрос на каждое здание.
